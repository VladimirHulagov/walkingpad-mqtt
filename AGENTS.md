# AGENTS.md

Инструкции для ИИ-агентов, работающих с этим репозиторием.

## Проект

`walkingpad-mqtt` — BLE→MQTT мост для дорожки WalkingPad A1 Pro (WPA1F-Pro,
проприетарный WiLink-протокол KingSmith, сервис 0xFE00) и Home Assistant.
Python 3.11+, asyncio, src-layout. Полная документация: `README.md`;
дизайн и план — в `docs/superpowers/`.

## Окружение

- venv в `.venv`; все команды — через `.venv/bin/...`. Системный Python не трогать.
- На хосте-разработчике pypi.org недоступен (DNS-фильтр): pip.conf указывает на
  зеркало. Если сеть другая — `pip install -e '.[dev]'` работает и с PyPI напрямую.
- Зависимости: `ph4-walkingpad` (WiLink), `bleak` (BLE), `aiomqtt` (MQTT).
  Версии зафиксированы в `pyproject.toml`; пин-тесты семантики протокола —
  `tests/test_pad_protocol.py` (упали после обновления = семантика полей изменилась).

## Команды проверки

- Тесты (единственная автоматическая верификация, линтеров нет):
  `.venv/bin/pytest`
- Проверка CLI: `.venv/bin/walkingpad-mqtt --help`
- Сервис продакшена — systemd user-unit:
  `systemctl --user status|restart walkingpad-mqtt`, логи:
  `journalctl --user -u walkingpad-mqtt -f`

Перед завершением любой задачи — полный прогон pytest, все зелёные.

## Правила кода

- Комментарии и документация — на русском (сложившаяся конвенция репозитория).
- Коммиты: conventional style (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).
- Никаких секретов в репозитории: MAC реальной дорожки, адрес брокера, креды
  живут только в `~/.config/walkingpad/config.toml` (вне репо). В коде и
  тестах — плейсхолдеры (`AA:BB:CC:DD:EE:FF`, `localhost`).
- Архитектура: модули в `src/walkingpad_mqtt/` изолированы, склека только в
  `main.py`. Сигнатуры `StatusSample`/`Session`/`Command`/колбэков PadClient/
  MqttLayer — контракт между модулями; менять только с обновлением всех
  потребителей и тестов.
- Тесты не трогают реальный BLE и реальный брокер: BLE-слой тестируется через
  `FakeController`, MQTT — через фейки/билдеры пейлоадов.

## Отладка на реальном устройстве

- `--discover` — найти MAC дорожки (дорожка должна рекламироваться).
- Аварийные ситуации: висячий BlueZ-линк лечится `bluetoothctl disconnect <MAC>`
  (сервис делает это сам после 3 неудач подряд).
- Поведение дорожки: команды `start`/`speed` работают только после активации
  режима (`switch_mode(1)` — сервис шлёт её сам при подключении); из сна
  дорожка команды игнорирует. Одно BLE-подключение одновременно: телефон-приложение
  и мост взаимоисключающи.
