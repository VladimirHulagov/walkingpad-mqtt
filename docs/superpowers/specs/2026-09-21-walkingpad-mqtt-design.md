# WalkingPad A1 Pro → MQTT мост (walkingpad-mqtt)

Дата: 2026-09-21
Статус: утверждён (дизайн), ожидает реализации

## Контекст

WalkingPad A1 Pro (WPA1F-Pro) — дорожка для walking desk. Связь только по BLE
(Wi-Fi нет). Использует проприетарный KingSmith WiLink-протокол: сервис
`0xFE00`, notify-характеристика `0xFE01`, write `0xFE02`. Статус (состояние
ремня, скорость, время, дистанция, шаги) отдаётся по опросу; приложение
WalkingPad опрашивает ~750 мс. Калории дорожка не отдаёт. Одновременно
поддерживается только одно BLE-подключение.

Протокол реверс-инжинирен сообществом; готовая Python-библиотека
`ph4-walkingpad` (на `bleak`) поддерживает A1/A1 Pro.

Пользователь: слушает Bluetooth-музыку на этом же ноутбуке (X1 Yoga, hci0) —
BLE-дорожка и A2DP сосуществуют, но постоянное сканирование нежелательно.

Инфраструктура: MQTT-брокер и Home Assistant уже развёрнуты.

## Цели

1. Постоянный мониторинг дорожки: скорость, дистанция, шаги, длительность
   сессии, расчётные калории — в Home Assistant через MQTT discovery.
2. Управление из HA: старт, стоп, установка скорости.
3. Сервис владеет BLE-подключением постоянно; официальное приложение не
   используется.

## Не-цели (non-goals)

- Совместная работа с приложением WalkingPad на телефоне (протокол не
  позволяет два подключения).
- Локальная БД истории — историю ведёт HA (recorder) через сенсоры.
- OTA, калибровка, режимы auto — только базовое управление.
- Поддержка других моделей (FTMS: KS-HD-* и т.п.) — архитектура позволяет
  добавить позже, но не входит в объём.

## Архитектура

```
WalkingPad A1Pro ──BLE(WiLink 0xFE00)──> walkingpad-mqtt ──MQTT──> брокер ──> Home Assistant
                                         (Python, asyncio,
                                          systemd user-unit,
                                          хост: ноутбук с BLE)
```

**Стек**: Python 3.10+, asyncio, `bleak`, `ph4-walkingpad` (WiLink-бэкенд),
`aiomqtt`. Конфигурация TOML. Unit-тесты `pytest`.

**Конфиг** `~/.config/walkingpad/config.toml`:

```toml
[ble]
mac = "57:4C:4E:AA:BB:CC"   # MAC дорожки (уточняется при первом запуске --discover)
adapter = "hci0"           # опционально; на случай выделенного донгла

[calories]
weight_kg = 80.0
coefficient = 1.03          # ккал на (кг × км), ходьба

[mqtt]
host = "..."
port = 1883
username = "..."
password = "..."
prefix = "walkingpad"       # базовый топик
discovery_prefix = "homeassistant"

[polling]
interval_s = 1.0
```

Секреты допускается брать из переменных окружения
(`WALKINGPAD_MQTT_PASSWORD` и т.п.) поверх значений файла.

## Компоненты

### 1. BLE-клиент (`pad_client.py`)

Обёртка над `ph4_walkingpad.Controller`:

- Подключение по MAC; без постоянного сканирования.
- Опрос статуса раз в `polling.interval_s` (по умолчанию 1.0 с).
- При подключении один раз читает параметры (max speed) для границ слайдера;
  fallback: 0.5–6.0 км/ч из конфига.
- Пауза ≥ 300 мс между write-командами (пейсинг WiLink).
- Экспонирует колбэки: `on_status(status)`, `on_disconnect`.

**Переподключение**: при потере связи — пауза 5 с, короткое окно сканирования
(~5 с, фильтр по MAC/имени), попытка подключения; бэкофф ×2 до 60 с; после
успеха — сброс бэкоффа. Пока связи нет, сенсоры публикуются как
`unavailable`.

**Восстановление сессии**: дорожка хранит в памяти статистику последней
пробежки (last status), отдаёт её по отдельному запросу и очищает. После
переподключения (и если сессия не была корректно закрыта) клиент запрашивает
last status и публикует финальную статистику сессии.

### 2. Детектор сессий (`sessions.py`)

Вход: поток статусов; поле `state` (enum WiLink: standby/stop/run/...).

- Переход `running` → «сессия открыта»; накопление пиковых значений
  (дистанция/шаги/время монотонно растут внутри сессии — берём текущие).
- Переход в `stopped` → сессия закрыта: публикация финального рекорда.
- Защита от моргания: гистерезис 3 с (кратковременные переходы не закрывают
  сессию).
- Сброс счётчиков дорожки между сессиями отслеживается по обнулению
  дистанции/шагов.

### 3. MQTT-слой (`mqtt_layer.py`)

**Топики** (префикс `walkingpad`):

| Топик | Направление | Payload |
|---|---|---|
| `walkingpad/availability` | pub | `online` / `offline` (LWT) |
| `walkingpad/state` | pub | JSON: `speed`, `distance`, `steps`, `session_time_s`, `belt_state`, `calories`, `connected` |
| `walkingpad/session` | pub | JSON финальной статистики закрытой сессии |
| `walkingpad/command` | sub | JSON: `{"cmd":"start"}`, `{"cmd":"stop"}`, `{"cmd":"speed","value":4.0}` |
| `walkingpad/speed/set` | sub | число км/ч (удобно для number-энтити HA) |

**Home Assistant discovery** (`homeassistant/<type>/walkingpad/<name>/config`):

- Сенсоры: скорость (км/ч), дистанция сессии (км), шаги сессии (шт),
  длительность сессии (с), калории сессии (ккал), состояние ремня
  (enum/текст), BLE-связь (binary_sensor).
- Управление: `button.start`, `button.stop`, `number.speed`
  (границы из параметров дорожки, шаг 0.5).

Все энтити привязаны к `availability_topic`. Публикация state — с retain
(последнее значение переживает перезапуск HA/сервиса), discovery — retain.

### 4. Оценка калорий (`calories.py`)

`ккал = weight_kg × distance_km × coefficient` (коэффициент по умолчанию
1.03 — стандартная метрика ходьбы). Считается на лету от дистанции сессии.

### 5. Точка входа (`main.py`) + systemd

`main.py` собирает компоненты; `--discover` — утилита первого запуска:
сканирует эфир, печатает MAC устройств с именами `WalkingPad*`/`WPA1F*` и
уходит. Systemd user-unit `~/.config/systemd/user/walkingpad-mqtt.service`
(`Restart=always`, `WantedBy=default.target`).

## Поток данных

1. Колбэк статуса (1 Гц) → детектор сессий → актуализация state-JSON →
   публикация `walkingpad/state` (только при изменении, не чаще 1/с).
2. Команда из HA → валидация (скорость в границах, подключение активно) →
   очередь команд (последняя `speed` выигрывает, debounce 300 мс) → write в
   `0xFE02` с пейсингом.
3. Закрытие сессии → публикация `walkingpad/session` (retain) + обновление
   сенсоров.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| BLE-разрыв / дорожка спит / обесточена | reconnect-цикл (бэкофф 5→60 с), сенсоры `unavailable`; availability `offline` публикуется брокером только при падении самого сервиса (LWT) |
| MQTT-брокер недоступен | retry с бэкоффом; телеметрия не буферизуется; BLE-подключение сохраняется |
| Невалидная команда | лог + игнор |
| Скорость вне диапазона | клиппинг к границам + лог |
| Дорожка не найдена при --discover | понятная ошибка, подсказки |

## Тестирование

- **Unit**:
  - парсер WiLink-фреймов — на реальных hex-дамперах
    (пример статуса: `f8a2010f01000fd10000ab0012ae3c0000003afd` →
    1.5 км/ч, 4049 с, 1.71 км, 4782 шага);
  - детектор сессий: сценарии старт/стоп/моргание/обнуление/разрыв;
  - калории;
  - валидация команд.
- **Интеграционные** (мок `Controller`): последовательности статусов →
  ожидаемые публикации MQTT (мок-брокер); reconnect-сценарии.
- **Ручные**: чек-лист на реальной дорожке: подключение, старт/стоп/скорость
  из HA, разрыв питания во время сессии и восстановление статистики,
  параллельное A2DP-аудио.

## Риски и допущения

- A1 Pro использует WiLink-протокол — подтверждено сообществом; если
  попадётся ревизия на FTMS — библиотека `mcdax/walkingpad-controller`
  покрывает оба (запасной вариант, не входит в объём).
- Интерференция с A2DP минимальна; при проблемах — выделенный USB-донгл
  (`ble.adapter` в конфиге уже предусмотрен).
- Last-status в памяти дорожки не переживает отключение питания — финальная
  статистика сессии может теряться при обесточивании сразу после ходьбы;
  телеметрия 1 Гц это существенно смягчает.
